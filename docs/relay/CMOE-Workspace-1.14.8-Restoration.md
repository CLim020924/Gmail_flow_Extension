- 업데이트 피드 버전과 GitHub 릴리스 폴더·설치 파일명이 정확히 일치해야 다운로드한다.
- 다운로드 중 취소할 수 있고, 취소·오류 시 `.partial` 파일을 제거한다.

- Electron 단일 인스턴스 잠금과 두 번째 실행의 기존 창 복원·포커스 동작을 유지한다.

- 원인은 앱 종료와 PowerShell 설치 보조 프로세스의 기존 PID 확인 사이 경쟁 조건으로 판단했다. 기존 앱이 이미 정상 종료된 경우에는 검증된 설치를 계속하고, 경로가 다른 살아 있는 PID는 계속 거부한다.
- 설치 실패 시 기존 앱을 `--update-failed`로 다시 열어 실패 사실을 표시하고, 저장·백업 실패 시 설치 예약을 폐기한다.
- 업데이트 버튼을 누르는 즉시 어느 화면에서나 전역 진행창을 열어 연결·다운로드·SHA-256 검증·작업 저장·로컬/Drive 백업·설치·자동 재실행을 단계별로 표시한다. 재실행 후에는 완료 버전을 표시한다.

## 1.15.33 업데이트 후 바로가기·버전 인계 고정

- 업데이트 설치 시 기존 바탕화면·시작 메뉴 기본 바로가기를 새 설치 EXE 대상으로 다시 만들어 대상 경로와 아이콘 메타데이터를 갱신한다. 사용자가 바탕화면 바로가기를 직접 삭제했다면 설치기가 임의로 되살리지 않는다.
- 업데이트된 앱은 `--updated` 시작 시 두 기본 바로가기를 현재 `process.execPath`로 한 번 더 확정하고 `installed-version.json`에 버전과 실제 실행 경로를 기록한다.
- 설치 helper는 새 파일의 FileVersion이 기대 버전과 같은지 확인한 뒤 그 정확한 EXE를 `--updated`로 한 번 실행한다. 실패한 경우에만 기존 경로를 `--update-failed`로 연다.
- 새 설치부터 경로 선택을 막고 사용자별 고정 설치 위치를 사용한다. 기존 설치는 같은 AppId와 등록 경로를 따라 인플레이스 업데이트한다.
- 전체 Node 검사, 빌드 사전검사, 개발판 11개 가이드·215단계 스모크와 패키지판 스모크가 통과했다. 설치형은 `workspace/desktop-dist/CMOE-Workspace-Setup-1.15.33-Windows.exe`, 크기 `111,029,881` bytes, SHA-256 `2DEC2EC47A6495B729C81691B19F455F7D75AACFE9E84EA6ED8A5D97E5611A92`, FileVersion 1.15.33, 서명 없음이다.
- 사용자 요청에 따라 이 PC의 현재 1.15.31 설치본은 변경하지 않았다. 실제 앱 내 1.15.31→1.15.33 업데이트와 Windows 아이콘 표시 확인은 사용자가 직접 시험한다.

## 1.15.34 종료 대기 경쟁 조건 수정

- 실제 1.15.31 앱에서 1.15.33 설치기를 내려받고 로컬 백업까지 만들었지만 설치·재실행되지 않는 현상이 두 번 발생했다. 바탕화면과 시작 메뉴 링크는 모두 정식 설치 경로였으므로 다른 아이콘 문제가 아니었다.
- 같은 캐시 설치기를 앱 종료 상태에서 `/S`로 직접 실행하면 exit 0으로 성공했고 설치 EXE·등록 버전·두 기본 바로가기가 모두 1.15.33을 가리켰다. 새 앱도 해당 경로에서 `--updated`로 실행했다.
- helper의 `Get-Process`와 `Wait-Process -ErrorAction Stop` 사이에 앱이 종료되는 경쟁 조건을 제거했다. 경로를 얻을 수 있을 때만 process identity를 확인하고, 이미 종료된 PID는 정상으로 취급한다. 설치기에는 `/S`만 전달하고 새 앱에만 `--updated`를 전달한다.
- 1.15.34 설치형은 `workspace/desktop-dist/CMOE-Workspace-Setup-1.15.34-Windows.exe`, 크기 `111,029,704` bytes, SHA-256 `07182921E044D6596F84E0F2312C08A7F10A3A067446F957D488133A6D6C740C`, FileVersion 1.15.34, 서명 없음이다.
